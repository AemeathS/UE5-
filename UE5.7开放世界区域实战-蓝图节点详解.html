阶段五  整合发布     → PIE（在编辑器中运行测试） 测试清单、性能优化、打包（第 13 章）

    3. World Partition：开放世界的地基（策划视角）

    3.1 它在解决什么问题

    UE5 之前的关卡是"整张地图全部加载"。2km×2km 的地形 + 几千棵植被，内存和帧数直接爆炸。World Partition 把世界切成流送单元（Grid），只加载玩家附近的一圈，远处自动卸载。

    3.2 你需要知道的三个概念

  • •网格单元（Grid）：默认 2km 分区，玩家周围 N 个单元流送进/出，对你透明
  • •Data Layer（数据层）：按"类型"分组加载，比如 环境、NPC、任务道具 各一层
  • •用途：任务做到"夜间"才加载 NPC，做到"进门"才加载宝箱——玩法控制加载
  • •HLOD（分层细节层级）：远处多个 Actor 合并成一个低模代理（第 13 章优化部分细讲）

    • 3.3 蓝图侧：和 World Partition 有关的两件事

    ① 流送状态查询（可选，一般用不到，但要认识）：

    Event BeginPlay（事件 开始运行）
  └─> Get Streaming Level（获取流送关卡，关卡引用）
        └─> Is Level Streaming（关卡是否流送）
              └─> Branch（分支） → 输出对应提示

    ② 真正要紧的：GameMode / 全局单例不要放在关卡 Actor 里

    World Partition 关卡里放 BeginPlay 就执行的全局逻辑，会随流送单元卸载而失效。正确的挂载位置：

    全局逻辑正确宿主
    任务管理器 QuestManagerGameInstance（游戏实例，跨关卡存活）
    背包 / 进度数据SaveGame（存档） 对象
    玩家角色GameMode 生成，天然全局唯一
    坑
    在 WP 关卡里用 Get All Actors Of Class（获取所有Actor，按类） 查"全图 NPC"只查得到当前已流送的单元，别用它做全图统计——那是数据层/任务系统的活，不是蓝图搜索的活。

    4. Landscape（地形）与地表材质

    4.1 建地形：参数先定对，后面少返工

    打开地形模式（左上角模式面板的 Landscape 图标），切到"创建"，先设参数再拖到场景：

    参数建议值说明
    Section Size253越小 LOD 过渡越平滑。505 省性能但远看容易"裂"，新手用 253
    Sections Per Component1×1简单省心。2×2 能省 DrawCall，但 LOD 纹理更容易糊
    分辨率2km 区域用 2029（低配 1009）约 1 像素 ≈ 1 米，决定雕刻精度
    高度范围默认（-256 ~ 256）之后不够再调

    操作：点"创建"，在地图上拖动放置，位置尽量居中于玩法区域。

    坑
    1：World Partition 项目里地形会自动切成流送网格单元，别手动拆，它自己会处理。 坑 2：UE5.3+ 地形工具新增"流式（Flow）"雕刻模式，功能强但学习曲线陡。新手把模式切回"标准"用。

    4.2 雕刻：三层笔刷法

    原则一句话：先整体、后细节，每层换一次笔刷思路。

    第 1 层  大笔刷（半径 2000+）→ 拉山体起伏、盆地、主脊线     ← 定"势"
第 2 层  中笔刷（半径 800）  → 坡道、悬崖、河谷走向          ← 定"路"
第 3 层  小笔刷（半径 200）  → 凸起、坑洼、河床细节          ← 定"戏"

    基本操作：

  • •左键拖动：按当前工具雕刻
  • •Ctrl + 左键：反向（填 ↔ 挖）
  • •Shift + 左键：平滑（修陡峭、去刷痕）
  • •笔刷大小 / 强度 / Falloff：在细节面板调

    • 三个心法：

  • •每画一道坡，问一句"玩家怎么走上去"——45° 以上必须有绕路或可攀爬面，否则是死区
  • •悬崖做"上缓下陡"：顶部缓坡（能上去跳下），底部陡（有围合感）
  • •收尾用平滑笔刷去掉笔刷纹（一道一道的刷子痕迹）
    • 坑
    想要"自然侵蚀感"别硬刷。启用 Landmass（陆块） 插件用其侵蚀笔刷，或留给材质做"坡度混合"（见 4.5），比手刷快十倍。

    4.3 地表材质：Material Layer 图层系统（推荐做法）

    UE5 推荐用材质图层（Material Layer）——把草地/岩石/泥地做成可复用图层资产。别用老式 LandscapeLayerBlend 把一堆节点糊在一个材质里（老式做法见 4.4）。

    第 1 步：做三个图层资产

    内容浏览器 → 右键 → 材质 → 材质层（Material Layer），建 ML_Grass、ML_Rock、ML_Mud。

    第 2 步：填每个图层内容（以 ML_Grass 为例）

    每个 Material Layer 自带 LandscapeLayerWeight（地形图层权重） 节点（图层与地形权重的"插槽"），把插槽参数名改成 grass 方便识别：

    LandscapeLayerWeight（地形图层权重，插槽名 grass）
  ├─> Texture Sample（纹理采样，草地颜色贴图） → MakeMaterialAttributes → 基础颜色
  ├─> Texture Sample（纹理采样，草地法线）     → 法线
  └─> Texture Sample（纹理采样，草地粗糙度）   → 粗糙度
        └─> 全部汇入 MakeMaterialAttributes（构成材质属性）
              └─> 输出 → 材质属性（Material Attributes）

    岩石、泥地重复同样接法（换贴图、插槽名改 rock / mud）。

    第 3 步：主材质把图层"叠"起来

    新建材质 M_Landscape，搜节点 `Material Attribute Layers`（材质属性图层），把三个 ML 拖进它的图层数组：

    ML_Grass ──┐
ML_Rock  ──┼──> Material Attribute Layers（材质属性图层）──> 输出（材质属性）
ML_Mud   ──┘       属性：Blend Type = 高度混合（Height Blend）
  • •Blend Type 选"高度混合"：图层按各自高度图自动过渡，草地到岩石是"岩石顶出草地"的自然咬合，不是生硬切边
  • •每个图层加一个 LandscapeLayerCoords（地形图层坐标） 控制贴图平铺大小（草地 200 / 岩石 400 / 泥地 300，按体感调）

    • 第 4 步：让材质能用于地形

    材质详情面板 → 用法（Usage）→ 勾选 `Used with Landscape`（用于地形） → 保存 → 指定给地形。

    第 5 步：刷权重

    地形模式 → 切到"权重"子模式 → 选图层（grass/rock/mud）→ 在地形上涂抹。

    目标做法
    草地只长在平地权重笔刷开坡度过滤器（>45° 不刷）
    悬崖自动露岩石不手刷，靠材质坡度混合自动出（见 4.5）
    过渡自然刷完用权重笔刷的平滑（Shift）过渡边缘

    4.4 老式做法：LandscapeLayerBlend（备选，理解原理用）

    不建图层资产，直接在 M_Landscape 里用 LandscapeLayerBlend（地形图层混合） 装多层纹理：

    LandscapeLayerBlend（地形图层混合）
  ├─ 层 1：LandscapeLayerWeight（地形图层权重，Layer=草）   → 草地贴图 → BaseColor 等
  ├─ 层 2：LandscapeLayerWeight（Layer=岩石）               → 岩石贴图
  └─ 层 3：LandscapeLayerWeight（Layer=泥地）               → 泥地贴图
        └─> 混合输出 → 基础颜色 / 法线 / 粗糙度

    关键节点速查（两种做法都会用）：

    节点作用
    LandscapeLayerWeight（地形图层权重）读取地形笔刷刷出的权重贴图，按权重混合
    LandscapeLayerBlend（地形图层混合）多图层混合的容器版本
    LandscapeLayerCoords（地形图层坐标）生成 UV 坐标，让贴图在地表平铺
    Vertex Normal WS（世界空间顶点法线）用于"坡度混合"（见 4.5）
    提示
    选型：新项目用 Material Layer（4.3），老项目/快速原型用 LandscapeLayerBlend（4.4）。两者效果都能到，Material Layer 的可维护性好得多。

    4.5 地表质感三件套（做完观感立刻升级）

    ① 坡度自动混合（悬崖自动露岩石，不用手刷——全文档地编观感提升最大的一个链路）

    Vertex Normal WS（世界空间顶点法线）
  └─> Dot（点积）(0,0,1)     → 0=垂直悬崖，1=水平地面
        └─> Constant Bias Scale（常量偏置缩放）→ 把 0~1 映射到 0.3~0.7
              └─> Lerp（线性插值，在草地质感 和 岩石质感 之间插值）
                    └─> 输出 → BaseColor / Normal / Roughness

    ② 防止贴图拉伸（陡坡草地被拉花）：对草图层加世界空间混合，或三平面映射（按法线在三轴采样混合）。

    ③ 草地风动：搜节点 `SimpleGrassWind`（草风函数） → 输出接 World Position Offset（世界位置偏移），风强度 0.1~0.3。整个地表立刻"活"起来。

    坑
    地表材质 Metallic 固定 0，Roughness 0.6~0.9。Metallic 高会让大片地表闪成一片。

    4.6 地形蓝图：山体碰撞和物理材质

    地形一般不需要蓝图。只有"踩上去要有声音/脚印"这类需求时，用到物理材质 + 脚步声 Event：

    （角色动画蓝图 AnimBP）
Event Footstep
  └─> Line Trace By Channel（按通道进行线条追踪，向脚下打一条 100cm 的线）
        └─> Get Hit（获取命中结果） → Get Physical Material（获取物理材质）
              └─> Switch on Physical Material（基于物理材质切换，草地/石头/泥）
                    └─> Play Sound 2D（播放二维声音，对应脚步声）

作用：角色走草地发"沙沙"声，走石板发"嗒嗒"声。

    5. 植被与自然细节（Foliage）

    5.1 建 Foliage Type（植被类型）：每个参数是什么

    内容浏览器选中树木/草的 Static Mesh（静态网格体）→ 拖进场景，或右键 → 植被类型（Foliage Type）。创建后选中它，在详情面板逐个设：

    参数建议值作用
    Density（密度）草 0.05~0.1 / 树 0.0005~0.002每平米数量。树要小到"单点种"级别
    Initial Seed Density（初始种子密度）0自动播种，先关掉，手动刷更可控
    Scale（缩放）随机 0.8~1.3大小不齐才有自然感
    Random Yaw / Pitch / Roll（随机旋转）Yaw 随机 360°；Pitch/Roll 0只转朝向，别乱翻
    Align to Normal（对齐法线）勾选树草贴山坡站立
    Align Max Angle45°超过该坡度的不种（草不爬悬崖）
    Cull Distance（剔除距离）草 30m / 灌木 60m / 树 300m超过距离整个消失
    Collision（碰撞）草 No Collision；树 阻挡草有碰撞会让玩家卡在半空
    Landscape Layers草选 grass 图层只让草长在权重>0 的草地——控制分布的王牌

    5.2 绘制顺序：先结构、后细节、再修

    打开植被模式，按这个顺序（顺序错了会返工）：

    第 1 轮  树（低密度笔刷，单点种在"该有树的地方"）   ← 定空间骨架
第 2 轮  灌木、大石头（补树下的中层）                ← 填空间
第 3 轮  草（高密度，大片涂抹）                       ← 铺地面
第 4 轮  复查：擦掉不该有的（路中间、玩家必经处）     ← 保证可玩性

    绘制手法：

  • •树要"点"不要"抹"：密度 0.001 级别，像点菜一样一颗一颗放；大片抹出来的树林全长得一样
  • •草要"抹"不要"点"：密度拉高、强度调低，来回涂，别一次涂满（会成块）
  • •配合 Erase（擦除） / Lasso Select（套索选择） 批量删误种区域
  • •种完立刻 Play，从玩家视角跑一圈：重点看穿模（草穿石头、树枝卡头）、视线遮挡（灌木太密挡住交互目标）
    • 提示
    地编纪律：植被密度从"玩家站着看"的视角调，不是从俯视图调。俯视图密密麻麻，进游戏全是草丛穿模。

    5.3 草的风动画（让地表活起来的最后一步）

    草的材质加 `SimpleGrassWind`（草风函数） 节点接 World Position Offset（世界位置偏移）（同 4.5 ③）。想做"玩家走过草被压倒"，用蓝图驱动（见 5.5）。

    5.4 性能红线与检查

  • •树/石头：能用 Nanite 就开（自动 LOD，远处几乎零成本）；草永远别开 Nanite（用普通 LOD + Cull Distance）
  • •刷完看 stat GPU（GPU 统计）：三角形数爆了先砍草密度，再砍灌木
  • •Build HLOD 之后必须 Play 复查植被——植被合并进 HLOD 后常见"远看全变形状"的 bug，发现问题把对应植被类型从 HLOD 排除

    • 5.5 蓝图侧：植被交互（可选进阶）

    例：玩家走进灌木丛，树叶轻微晃动

    原理：材质里用 World Position Offset 把顶点按噪声推开，蓝图控制开关。

    （灌木材质）
Time
  └─> Noise（噪点，噪声函数）
        └─> * 0.1（振幅）
              └─> 加到 World Position Offset（世界位置偏移）

（玩家角色蓝图）
Event BeginOverlap（事件 开始重叠，碰撞组件与灌木重叠）
  └─> Dynamic Material Instance（获取动态材质实例）
        └─> Set Scalar Parameter Value（设置标量参数值，参数 = 风强度）
    提示
    这是一个"蓝图 ←→ 材质"联动的经典案例：蓝图改参数，材质响应动画。动态材质实例（MID）是两者通信的桥梁。

    6. 光照、大气与后期（Lumen 体系）

    UE5 开放世界的视觉上限几乎全在光照。这一章几乎没有蓝图，但全是"组件 + 参数"，是地编阶段的验收时刻。

    6.1 一个可用的默认光照组合

    组件参数建议作用
    Sky Atmosphere（天空大气）默认天空颜色、地平线、大气散射
    Directional Light（定向光）（太阳）Intensity 8~10 lux，Cast Shadows（投射阴影）主光，控制昼夜方向
    Volumetric Clouds（体积云）默认云层，可被阳光穿过
    Exponential Height Fog（指数高度雾）Density 0.01~0.03远景雾，拉开层次感
    Sky Light（天光）Real Time Capture（实时捕获） 勾选天光补光，让阴影不是死黑
    Post Process Volume（后期处理体积）见 6.2全局色调、曝光

    6.2 Post Process Volume 节点/参数（无节点，全参数）

    参数建议作用
    Exposure（曝光） → Min/Max EV4~12，勾 Auto Exposure（自动曝光）从阴影走进阳光不刺眼
    Color Grading（色彩分级） → Saturation（饱和度）0.9~1.1调整体风格（废墟感往低饱和度走）
    Bloom（泛光）0.8~1.0高光柔化
    Ambient Occlusion（环境光遮蔽）0.6暗角接触阴影，立体感
    坑
    Post Process Volume 要勾 Unbound（无边界），否则只在体积框内生效，走出框画面突变。

    6.3 蓝图侧：昼夜循环（可选，但很"开放世界"）

    光照组件本身不是蓝图，但你要做"时间流逝 → 太阳转、天光变、曝光变"，就得用蓝图驱动：

    Event Tick（事件 刻度）
  └─> Time += Delta Seconds * 0.1（模拟时间流逝，可调倍率）
        ├─> Set World Rotation（设置世界旋转，太阳光：随时间绕 Z 轴转）
        └─> Get Directional Light（获取定向光） → Set Intensity（设置强度，晚上降低）

（配合材质参数）
  └─> Set Scalar Parameter Value（设置标量参数值，天空自发光强度，晚上变暗）
    坑
    昼夜切换别直接在 Tick 里瞬时改光强，会出现"闪烁"。用 Lerp（线性插值）（或 FInterp To（按时间插值到））过渡：
    Set Intensity（设置强度）
  └─> FInterp To（按时间插值到，当前值 → 目标值 → Delta Time → 插值速度）

    FInterp To 是蓝图里"任何数值平滑变化"的万能节点，后面交互高亮、UI 动画都会用到。

    6.4 实操：完整光照搭建五步（顺序别乱）

    第 1 步  放主光：Directional Light（定向光）
第 2 步  放天光：Sky Light（天光）
第 3 步  放大气：Sky Atmosphere（天空大气）
第 4 步  放体积云：Volumetric Clouds（体积云）
第 5 步  放雾 + 后期：Exponential Height Fog + Post Process Volume

    第 1 步 主光（太阳）

  • •放置面板拖 Directional Light
  • •参数：Intensity（强度）8~10；Cast Shadows（投射阴影）勾选；Light Color（光色）偏暖（255,240,220）
  • •关键：属性里勾 `Atmosphere Sun Light`（大气太阳光）——不勾，天空大气不认这个太阳，天空是平的
  • •旋转角度决定阴影方向和"时间段"：早/晚阴影长，正午阴影短

    • 第 2 步 天光

  • •Sky Light + 勾 Real Time Capture（实时捕获）：天空环境色实时取样，让阴影不是死黑
  • •Intensity 1 左右

    • 第 3 步 天空大气

  • •Sky Atmosphere 放任意位置，默认参数即可；前提是第 1 步勾了 Atmosphere Sun Light

    • 第 4 步 体积云

  • •Volumetric Clouds 放天空大气附近，参数默认；想云在地面投影阴影就勾 Cast Shadows（可选，开销大）

    • 第 5 步 雾 + 后期

  • •Exponential Height Fog：Density 0.01~0.03，Fog Color（雾色）偏蓝灰、匹配天空色
  • •Post Process Volume：勾 Unbound（无边界）；Exposure Min 4 / Max 12 + 勾 Auto Exposure；Saturation 0.9~1.1；Bloom 0.8；AO 0.6

    • 验收标准：从近到远看 2km——近景清晰、中景有层次、远景融进雾色；阴影不是死黑；天空有渐变不是纯白。

    坑
    1：最常见的"天空是平的"= 忘了勾 Atmosphere Sun Light。 坑 2：太阳角度 >60° 阴影太短没立体感、<10° 场景过暗，30~45° 最舒服。 坑 3：Auto Exposure 不勾 → 进阴影一片黑、出阳光一片白。

    • 8.2 Enhanced Input 接线（UE5 的新输入体系）

    UE5 用 Enhanced Input 代替旧的 InputAxis 节点。核心链路是三步：

    ① 资产层：IA_Move（Input Action，配置 Vector 2D（二维向量））
          IM_Default（Input Mapping Context，把 WASD 键绑定到 IA_Move）

② 绑定层（角色蓝图 Event BeginPlay（事件 开始运行））：
Event BeginPlay（事件 开始运行）
  └─> Get Player Controller（获取玩家控制器）
        └─> Cast To Player Controller（转换为玩家控制器）
              └─> Add Mapping Context（添加映射上下文）（IM_Default → Priority 0）
                   作用：把"按键 → 输入动作"的映射装进角色

③ 消费层（角色蓝图图表，右键输入 IA_Move）：
IA_Move（Triggered）
  └─> Add Movement Input（添加移动输入）
        ├─> World Direction = 相机前向（不是角色前向！）
        └─> Scale Value = 输入强度（0~1 控制速度）

    重点解释 `Add Movement Input（添加移动输入）` 的两个输入：

    IA_Move(输入值)
  └─> Break Vector 2D（拆分二维向量，把 X/Y 拆成"前后/左右"）
        ├─> Get Control Rotation（获取控制器旋转） → Break Rotator（拆分旋转体） → 取 Yaw（偏航角）
        │     └─> Make Rotator（构成旋转体）(0, Yaw（偏航角）, 0) → Get Forward Vector（获取向前向量，相机朝向）
        │           └─> * X 值  → Add Movement Input（添加移动输入） 的 World Direction
        └─> 同上取右向量 * Y 值
    提示
    为什么是"相机朝向"而不是"角色朝向"？因为第三人称游戏里，玩家按 W 期望的是"往屏幕看的方向走"，不是"角色脸的方向走"。这是新手第一个必踩的坑。

② 事件：

  └─> Get Character Movement（获取角色移动）
        └─> Set Max Walk Speed（设置最大行走速度，1200，跑起来）

  └─> Get Character Movement（获取角色移动）

    9. 交互系统（全文档最核心的蓝图教学）

    开放世界 80% 的玩法是"走到物体前，按 E 交互"。这一章从接口设计到节点链路完整过一遍。

    9.1 为什么必须用接口（Interface）

    你会有宝箱、NPC、开关、告示牌……如果给每个 Actor 单独写交互逻辑，E 键检测那边就要写一堆 Cast To A / Cast To B，加一个新东西就要改一次检测代码。

    接口解法：定义一个"可交互"的约定，谁想被交互，谁就实现这个接口。检测端只认接口，不认具体类型。

    Interface（接口）: I_Interactable
  ├─ Interact(Instigator)     → 交互发生时调用
  ├─ GetPromptText()          → 返回"按 E 打开宝箱"这样的提示文本
  └─ SetHighlight(Enabled)    → 高亮/取消高亮
    提示
    以后加新交互物：新建 Actor → Implement Interface（实现接口）→ 填三个函数，检测端一行不改。

    9.2 检测链路：每帧找"面前最近的可交互物"

    （角色蓝图）
Event Tick（事件 刻度）
  └─> Sphere Overlap Actors（球体重叠Actor，以相机位置为球心，半径 250）
        ├─> Object Types → 只选 World Dynamic（世界动态） / Pawn（操控者，别全选，省性能）
        └─> Actors to Ignore → Self（自身）
              └─> 输出 Actors 数组
                    └─> Filter（循环，用 Does Implement Interface（是否实现接口） 过滤掉不可交互的）
                          └─> 用 距离 排序 → 取最近的一个
                                └─> 存入变量 CurrentTarget

    循环过滤的节点链路：

    Get Actors（数组）
  └─> For Each Loop（遍历每个）
        └─> Does Implement Interface（是否实现接口，当前元素）
              ├─> 是 → 计算与玩家距离 → 存"最近"候选
              └─> 否 → 跳过

    角色朝哪看，就交互谁：把球心从"角色中心"换成"相机位置 + 相机前向 × 150cm"，就是"准星对准的东西"：

    Get Camera Component（获取相机组件） → Get World Location（获取世界位置）
  └─> + (Get Forward Vector * 150)
        └─> 作为 Sphere Overlap 的圆心

    9.3 高亮 + 提示 UI（每帧刷新的反馈）

    （接 9.2 找到 CurrentTarget 之后）
CurrentTarget
  ├─> 找到新目标
  │     └─> Call SetHighlight(True)（材质/描边亮起来）
  └─> 丢失旧目标（变量里的目标 ≠ 新目标）
        └─> 旧目标 Call SetHighlight(False)

CurrentTarget
  └─> Call GetPromptText()
        └─> Set Text（设置文本，UI 上的提示条，见第 12 章 Widget 绑定）
    提示
    关键点：上一帧的目标和这一帧的目标做比较。没变就不重复调用（省性能），变了才切高亮。用 Branch（分支） 判断"新目标 ≠ 变量里的目标"即可。这就是 Do Once（只执行一次） / Gate（门） 类节点的常见用途——避免每帧重复执行同一件事。

    9.4 按下 E 执行交互

    IA_Interact（Triggered）        ← 第 8.2 节那套输入绑定方式
  └─> 判断 CurrentTarget 是否有效（Is Valid）
        └─> Branch（分支）
              ├─> 有效 → CurrentTarget → Call Interact(Self)
              └─> 无效 → 什么都不做（或播放一个"无提示"音效）

    10. NPC AI：Behavior Tree（行为树） + 感知

    开放世界的"活人感"来自 AI：守卫会巡逻、发现玩家会追、追丢了会回岗。核心是三件套：AI Controller（AI控制器，大脑）、Blackboard（黑板，记忆）、Behavior Tree（行为树，行为逻辑）。

    10.1 三件套分工

    组件角色类比
    AI Controller（AI控制器）大脑中枢，驱动 Behavior Tree（行为树）司令部
    Blackboard（黑板）共享变量存储（目标是谁、有没有目标）黑板/记忆
    Behavior Tree（行为树）决策树，什么时候干什么作战手册

    10.2 搭建顺序（先黑板上，再树上，最后接线）

    ① Blackboard 键（变量）

    TargetActor（Object）   → 当前敌人（玩家）
HasTarget（Bool）       → 有没有目标
HomeLocation（Vector）  → 巡逻原点

    ② Behavior Tree 结构

    Root（根节点，Selector 选择器）
 ├─ 【追击分支】Decorator（装饰器）：Blackboard（黑板） 检查 HasTarget = True
 │    └─ Move To（移动到，Blackboard Key = TargetActor）→ 靠近后用能力攻击
 └─ 【巡逻分支】Decorator（装饰器）：HasTarget = False
      └─ Sequence（序列）
           ├─ Move To（移动到，Random Point in Radius，围绕 HomeLocation 300cm）
           └─ Wait（等待，2~3 秒，到达后停顿）
    提示
    为什么是 Selector（选择器） 而不是 Sequence（序列）？Selector（选择器） 是"选一个能执行的分支"——有目标就追击，没目标就巡逻，互斥。Sequence（序列） 是"按顺序全执行"，用错场景 AI 会卡死。

    ③ AI Controller 蓝图接线

    BP_Guard_AI（继承 AIController）
Event BeginPlay（事件 开始运行）
  └─> Run Behavior Tree（运行行为树，指定 BT_Guard 资产）
        └─> Set Blackboard Value as Vector（将黑板值设为向量，HomeLocation = 出生点）

    10.3 感知（Sight Sense）：让 AI 发现玩家

    AI Controller 加 AIPerception（AI感知） 组件 → 加一个 Sight Sense（视觉感知） 配置（视锥 90°、看到 1500cm）。

    （AI Controller 蓝图）
AIPerception（AI感知） → On Target Perception Updated（目标感知已更新时，事件）
  └─> 判断是否感知到（Success 标志）
        └─> Branch（分支）
              ├─> 感知到 → Cast To Character（转换为角色） → 是玩家？
              │           └─> Set Blackboard Value as Object（将黑板值设为对象，TargetActor = 玩家）
              │                 └─> Set Blackboard Value as Bool（将黑板值设为布尔值，HasTarget = True）
              └─> 丢失 → Set HasTarget = False
                        └─> Move To（移动到，HomeLocation 回岗）
    坑
    On Target Perception Updated（目标感知已更新时） 在"开始看到"和"失去视野"都会触发，必须靠事件自带的 Successed（或 bSuccess）参数区分。写错会变成"守卫永远在追空气"。

    10.4 巡逻改为沿路径（进阶）

    用 Spline（样条线）代替 Random Point，AI 走固定路线更有"设定感"：

    巡逻点 Actor → 加 Spline（样条线） Component → 沿线摆 4~6 个巡逻点

（AI Controller 或守卫 Actor 蓝图）
Event BeginPlay（事件 开始运行）
  └─> Get Spline（获取样条线） → Get Number of Spline Points（获取样条线点数）
        └─> 存变量 WaypointIndex = 0

（Behavior Tree 的 Move To（移动到） 需要路径点时，从黑板上取）
→ Set Blackboard Value as Vector（将黑板值设为向量）
    = Spline（样条线） → Get Location at Distance Along Spline（获取样条线上指定距离的位置，按 WaypointIndex 取点）
  → 到达后 WaypointIndex + 1，取模循环
    提示
    这里用到的思路：BT 节点负责"决策"，具体"怎么取坐标/怎么算"放回蓝图里算好，塞进黑板。BT 里不放复杂计算，BT 只做 if/else 式的分支判断。

    10.5 攻击/被攻击（让玩家能反制）

    （守卫收到伤害时）
Event Any Damage（事件 任何伤害）
  └─> Set Blackboard Value as Object（将黑板值设为对象，TargetActor = 攻击者）
        └─> Set HasTarget = True（被打立刻反击，这就是"警觉"）

（玩家攻击链路，见第 9 章交互基础上扩展）
IA_Attack（Triggered）
  └─> Sphere Overlap Actors（球体重叠Actor，面前小范围）
        └─> Apply Damage（应用伤害，对范围内敌人造成伤害）

### 10.6 实操：从零搭守卫（4 步）
  • •建黑板 BB_Guard：加 3 个键

  • •建 AI 控制器 BP_Guard_AI（继承 AIController）：

    11. 任务系统：让区域有"目标感"

    11.1 设计：任务数据放哪

    别把任务写死在蓝图里——写死一个任务，加第二个要复制整个蓝图。正确做法：任务数据用 DataTable（数据表），蓝图只写"引擎"。

    任务数据表结构（QuestTable）：

    字段类型示例
    QuestIDNameQuest_RepairTower
    TitleText修复瞭望塔
    DescriptionText收集 3 个齿轮，修复塔顶信号灯
    ObjectiveTargetint3（需要收集的数量）
    ObjectiveTagNameCollect_Gear（用于事件匹配，见下）
    RewardItem资产引用武器蓝图

    11.2 任务管理器 QuestManager（核心：Event Dispatcher（事件分发器） 用法）

    QuestManager 放 GameInstance（跨关卡、跨流送存活，见第 3 章）。它是全局唯一的"任务数据库"。

    BP_QuestManager（继承 GameInstance（游戏实例））
变量：
  ActiveQuests（Map：QuestID → 当前进度 struct）
  CompletedQuests（数组）

事件分发器（Event Dispatcher）：
  OnQuestStarted / OnQuestUpdated / OnQuestCompleted

函数：
  TryStartQuest(QuestID)：读 DataTable（数据表） → 已接？→ 加入 ActiveQuests → 广播 OnQuestStarted
  UpdateObjective(QuestID, ObjectiveTag)：匹配 Tag → 进度 +1 → 达标？
      → 是 → 标记完成 → 广播 OnQuestCompleted
      → 否 → 广播 OnQuestUpdated

    11.3 节点链路：接任务（和交互系统对接）

    （告示牌/任务 NPC，实现 I_Interactable）
Interact(Instigator)
  └─> Get Game Instance（获取游戏实例） → Cast To BP_QuestManager（转换为 BP_QuestManager）
        └─> TryStartQuest(Quest_RepairTower)

（QuestManager 内部）
TryStartQuest
  └─> Get Data Table Row（获取数据表行，按 QuestID 查任务配置）
        └─> 判断是否已在 ActiveQuests（Find）
              └─> Branch（分支）
                    ├─> 未接 → Add（写入 ActiveQuests）
                    │        └─> OnQuestStarted.Broadcast（广播）
                    └─> 已接 → 什么都不做（防止重复接）
    提示
    关键节点：Event Dispatcher.Broadcast（广播）。它让 QuestManager 的改动主动通知所有关心的人（UI、音效、奖励系统），不需要 UI 每帧去查任务——这就是蓝图里的"观察者模式"。

    11.4 节点链路：任务进度更新（事件匹配）

    核心设计：玩法事件打 Tag，任务按 Tag 认领。宝箱只管"我提供了 Collect_Gear 事件"，不知道哪个任务需要它——解耦。

    （宝箱开箱处，第 9.5 节 Interact 里）
Interact
  └─> 播放动画/音效
        └─> Get Game Instance（获取游戏实例） → Cast To BP_QuestManager（转换为 BP_QuestManager）
              └─> UpdateObjective(Quest_RepairTower, "Collect_Gear")

（QuestManager 内部）
UpdateObjective
  └─> 从 ActiveQuests 找到该任务
        └─> 判断 ObjectiveTag 匹配？→ 匹配 → Progress += 1
              └─> Progress >= ObjectiveTarget？
                    ├─> 是 → 移入 CompletedQuests
                    │        ├─> 发放奖励（Spawn 武器到背包）
                    │        └─> OnQuestCompleted.Broadcast（广播）
                    └─> 否 → OnQuestUpdated.Broadcast（广播）

    11.5 完整数据流回看（务必理解这条主线）

    玩家按 E 读告示牌
  → Cast To QuestManager（转换为 QuestManager） → TryStartQuest
  → ActiveQuests 加入 → 广播 OnQuestStarted
  → UI 收到广播 → 显示任务栏
  → 玩家开宝箱 → 宝箱广播 Collect_Gear
  → QuestManager 匹配 Tag → 进度 +1 → 广播 OnQuestUpdated
  → UI 刷新进度（3/3）
  → 达标 → 广播 OnQuestCompleted → UI 弹完成提示 → 发奖励
    提示
    这条链路的精髓：所有模块之间不直接互相引用，全靠 QuestManager 中转 + 广播。加第 100 个任务，宝箱、UI、玩家蓝图一个都不用改。

    11.6 实操：从零搭任务（5 步）

    1. 建结构体：内容浏览器右键 → 蓝图结构体 → FQuestInfo
   字段：QuestID(Name) / Title(Text) / Description(Text)
        / ObjectiveTarget(int) / ObjectiveTag(Name)
2. 建数据表：右键 → 数据表 → 行结构选 FQuestInfo → QuestTable
   加一行：Name = Quest_RepairTower，填好各字段（示例见 11.1）
3. 建 QuestManager：蓝图类 → 父类 GameInstance → BP_QuestManager
   实现：ActiveQuests / CompletedQuests 变量
         OnQuestStarted / OnQuestUpdated / OnQuestCompleted 三个 Event Dispatcher
         TryStartQuest / UpdateObjective 函数（链路见 11.3~11.4）
4. Project Settings → Game Instance Class 指定 BP_QuestManager
   ★ 这步最容易被忘，忘了 Cast To BP_QuestManager 必然失败
5. 联动：告示牌实现 I_Interactable → Interact 里调 TryStartQuest
         宝箱开箱处调 UpdateObjective（见 11.4）

    验收标准：按 E 接任务 → 任务出现（UI 见第 12 章）；开 3 个箱子 → 进度 3/3 → 完成；重复接同一任务被拦截。

    坑
    1：Cast To BP_QuestManager 失败 → 先查第 4 步的 Game Instance Class 配没配。 坑 2：任务进度不动 → UpdateObjective 的 ObjectiveTag 要和 DataTable 里写的一字不差（大小写都算）。 坑 3：数据表加行时 Name 是唯一 Key，重名报错。
